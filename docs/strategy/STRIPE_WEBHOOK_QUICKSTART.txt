WHAT DOES IT DO?
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Event: checkout.session.completed
  → INSERT payments (session_id, customer_email, amount_cents, currency, status='paid')
  → UPDATE lead_captures SET status='customer' WHERE email=customer_email
  Purpose: Track revenue, tag leads as customers for nurturing

Event: invoice.payment_succeeded
  → UPDATE subscriptions SET status='active', next_billing_date=...
  Purpose: Keep subscription lifecycle up-to-date

Event: invoice.payment_failed
  → UPDATE subscriptions SET status='payment_failed'
  → INSERT alerts FOR SALES TEAM
  Purpose: Alert team to retry payments, prevent churn

Event: customer.subscription.deleted
  → UPDATE subscriptions SET status='canceled', canceled_at=NOW()
  Purpose: Track cancellations

ALL EVENTS:
  → INSERT stripe_events (for idempotency deduplication)
  → INSERT audit_log (for compliance and debugging)

SETUP IN 5 MINUTES
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

1. APPLY DATABASE MIGRATION
   $ cd supabase
   $ supabase db push

2. DEPLOY CODE
   $ git add src/app/api/webhooks/stripe/route.ts supabase/migrations/00003_stripe_payment_tracking.sql
   $ git commit -m "Add Stripe webhook handlers for payment tracking"
   $ git push origin main
   (Vercel auto-deploys)

3. GET WEBHOOK SECRET FROM STRIPE
   → Go to https://dashboard.stripe.com/webhooks
   → Add endpoint: https://app.authichain.com/api/webhooks/stripe
   → Events: checkout.session.completed, invoice.payment_succeeded,
              invoice.payment_failed, customer.subscription.deleted
   → Click "Reveal signing secret" → Copy (starts with whsec_)

4. ADD ENVIRONMENT VARIABLE IN VERCEL
   → https://vercel.com/dashboard/settings/environment-variables
   → Add: STRIPE_WEBHOOK_AUTHICHAIN_SECRET = (paste secret from step 3)
   → Environments: Production, Preview, Development

5. REDEPLOY FOR ENV VAR TO TAKE EFFECT
   → Vercel → Deployments → Click latest → Redeploy

DONE! Webhooks are now active.

DATABASE SCHEMA AT A GLANCE
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

payments
  session_id (pk) | customer_email | amount_cents | currency | status | created_at | updated_at
  Example: cs_test_xxx | customer@example.com | 1999 | usd | paid | 2026-06-25 | 2026-06-25

subscriptions
  subscription_id (pk) | customer_email | product_id | status | next_billing_date | canceled_at | created_at | updated_at
  Example: sub_test_xxx | customer@example.com | prod_123 | active | 2026-07-25 | NULL | 2026-06-25 | 2026-06-25

alerts
  id (uuid, pk) | type | message | customer_email | metadata | resolved_at | created_at
  Example: uuid | payment_failed | "Payment failed for subscription sub_xxx" | customer@example.com | {...} | NULL | 2026-06-25

audit_log
  id (uuid, pk) | event_type | event_id | status | payload | created_at
  Example: uuid | stripe_webhook.checkout.session.completed | evt_test_xxx | success | {...} | 2026-06-25

stripe_events
  event_id (pk) | event_type | processed_at
  Example: evt_test_xxx | checkout.session.completed | 2026-06-25
  Purpose: Deduplication — prevents processing the same Stripe event twice

MONITORING YOUR WEBHOOKS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Revenue Today (SQL)
  SELECT SUM(amount_cents) / 100.0 FROM payments
  WHERE DATE(created_at) = CURRENT_DATE AND status = 'paid';

Failed Payments Alert (SQL)
  SELECT * FROM critical_alerts WHERE type = 'payment_failed'
  ORDER BY created_at DESC;

Webhook Error Rate (SQL)
  SELECT event_type, COUNT(*) as total,
    SUM(CASE WHEN status = 'error' THEN 1 ELSE 0 END) as errors
  FROM audit_log WHERE created_at > NOW() - INTERVAL '24 hours'
  GROUP BY event_type;

TROUBLESHOOTING
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Problem: Webhook returns 500
  → Check Vercel Logs: https://vercel.com/dashboard/logs
  → Verify STRIPE_WEBHOOK_AUTHICHAIN_SECRET is set
  → Verify database tables exist

Problem: Webhook returns 400 "Webhook Error"
  → Check Stripe Dashboard → Webhooks → Recent events → Click event for error details
  → Verify webhook secret matches the one in Stripe Dashboard

Problem: Payments table is empty
  → Check Stripe Dashboard → Webhooks → Event deliveries (look for ✗ failures)
  → Check Vercel Logs for errors
  → Verify webhook endpoint URL is correct: https://app.authichain.com/api/webhooks/stripe

Problem: Duplicate payments in database
  → This is EXPECTED — Stripe retries webhooks
  → Check stripe_events table to see dedup working
  → If you see duplicate ROWS (not retries), check audit_log for errors

Full troubleshooting guide: See docs/stripe-webhook-setup.md
